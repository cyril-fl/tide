# CLI

- Commands, help and flags are declared in `config/config.yaml` (`commands.<verb>-<noun>`), wired in `cmd/<verb>.go`, run by `cli/cmd-<verb>-<noun>/cmd.go`. New command: the `notes-cli-command` skill.
- `cmd/resolve.go` `apiResolved(kind, run)` turns paths (`/Projets/Idées`) into uuids in the args and `--parent` through `GET /api/resolve`, and `--content -` into stdin: commands only see uuids.
- Flags are read by a mill (`services/mill/`) that opens a huh form for what is missing; `noFlags()` drives the interactive path, and its test checks every flag of the config is declared.
- Edit commands change only what a flag asks for: `--pin` alone must not rewrite a note or a folder (see `cmd-edit-note`, `cmd-edit-folder`).
- Every command is a client of the API and never opens the base: it talks to the server through `services/apiclient` (generated by `make openapi`, session in `~/.config/tide/session.json`, `TIDE_URL`/`TIDE_SESSION` first). The admin's commands (`user add`, `user perf`, `user reset-password`, `rotate-secret`) and `serve` are those of `tide-server` (`cmd/tide-server/`, `core/server/`), the only binary on the base.
- The CLI and the MCP (`cmd-mcp/`) move together: a change to what one can do on the notes (a tool, an argument, a field of its output, a command, a flag) lands in the same change on the other, as a flag with `--json` on the CLI side or folded into an existing tool on the MCP side (few tools, short descriptions). Agents with a shell script the CLI instead of the MCP, so a gap breaks them. Exempt: screens (`finder`, `graph`), the session and account (`login`, `logout`, `whoami`, tokens), forms. A gap left on purpose gets a `TODO:` in the code and an issue.
- Output: plain text by default; every command that reads takes `--json` (not `finder`, `graph`: screens), `--yaml` only where it already is (`show tag`, `show token`); messages in English.
